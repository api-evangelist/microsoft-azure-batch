# Microsoft Azure Batch

> Azure Batch is Microsoft's managed job-scheduling and cluster-management service for
> large-scale parallel and high-performance computing workloads. You describe pools of VMs,
> jobs, and tasks; Batch allocates the compute, schedules the work, and tears it down.
> There is no charge for Batch itself — you pay for the virtual machines, storage and
> networking the pools consume.

## Two APIs, two planes

- **Data plane** — `https://{account}.{region}.batch.azure.com`. Jobs, job schedules,
  tasks, pools, nodes and applications. 51 paths, 72 operations, `api-version=2025-06-01`.
  OAuth scope `https://batch.core.windows.net//.default`.
- **Management plane** — `https://management.azure.com`. Batch accounts, application
  packages, pool ARM resources, private endpoints. 29 paths, 42 operations, standard ARM.

## What an agent needs to know before calling it

- **Auth.** Microsoft Entra ID OAuth 2.0 (managed identity or service principal) is the
  recommended path; a legacy HMAC shared-key scheme also exists. There is no granular
  scope surface — one `.default` scope per plane, and real permission comes from Azure
  RBAC role assignments on the Batch account.
- **Versioning.** `api-version` is a REQUIRED query parameter on every operation. Current
  is `2025-06-01`. An unrecognised value returns `UnsupportedRequestVersion` (400).
- **Ids are yours.** Job, pool, task and schedule ids are caller-supplied, not
  server-generated. Re-creating an existing id returns a `*Exists` conflict rather than a
  duplicate — which is the closest thing Batch has to create idempotency.
- **No Idempotency-Key.** 28 of 72 operations accept `If-Match` / `If-None-Match` for
  optimistic concurrency (`ConditionNotMet`, 412 on write / 304 on read). Creates have
  neither a conditional header nor a key.
- **Errors are not RFC 9457.** The envelope is `{code, message:{lang,value}, values[]}` in
  `application/json`. Microsoft publishes 125 error codes across four families.
- **Rate limits are quotas, not requests per minute.** Batch meters accounts, cores, jobs
  and pools. No `RateLimit-*` headers, no 429. Overload surfaces as `ServerBusy` (503).
  A brand-new account can have a dedicated-core quota of zero in some regions.
- **Long-running work polls the resource.** 14 operations return 202 Accepted; the caller
  polls the resource `state` (`resizing` -> `steady`, `deleting`) rather than an
  operation-status URL.
- **What can be undone.** `disable`/`enable`, `terminate`/`reactivate` (tasks) and
  `resize`/`stopresize` are reversible. `delete` — of a job, task, pool or node — is not,
  and `removenodes` destroys the nodes and any task state on them. A completed task can be
  reactivated only within its retention (7 days by default) and inside the 180-day maximum
  task lifetime.
- **No events.** Batch publishes no webhooks and is not an Event Grid source. State
  changes are observed by polling, or by routing Batch service logs to Azure Monitor.

## MCP

Microsoft ships the [Azure MCP Server](https://github.com/microsoft/mcp) (`@azure/mcp`,
stdio, no hosted endpoint). It has **no Azure Batch tool area** as of 2026-09-17, so there
is no MCP path to Batch jobs, pools or tasks. A candidate tool surface derived from the
REST contract is recorded in `mcp/microsoft-azure-batch-mcp.yml`.
